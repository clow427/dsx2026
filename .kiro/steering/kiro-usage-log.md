# Kiro Usage Log

The hackathon submission requires a write-up of how the team used Kiro. It lives in `docs/KIRO_USAGE.md`.

- After finishing meaningful work, add one row to the "Kiro usage log" table in `docs/KIRO_USAGE.md`. Include who did it (P1–P4), the spec task, which Kiro feature did the work (spec, steering, hook, PBT, MCP, power, or subagent), and a concrete outcome (a file, a test count, or a bug caught).
- Record only what actually happened. If a feature was configured but not observed working, say so. Don't claim a Kiro surface or power the team didn't use.
- When a hook, steering rule, or property test catches a problem, log it, including the falsifying input or blocked command. These are the most convincing entries.
- Keep each entry to one line. Link to files and commits instead of describing them.
